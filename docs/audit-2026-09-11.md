# Audit sécurité et accessibilité — Luna-prentissage

Date : 2026-09-11. Branche : `dev` (commit 21335d9). Périmètre : `app/`, `server/`, `nuxt.config.ts`, `scripts/`, `.github/`, dépendances. Audit statique (lecture de code + calcul de contrastes), pas de test d'intrusion ni de test avec lecteur d'écran réel.

---

## Partie 1 — Sécurité

### Ce qui est bien

- Toutes les requêtes SQL sont paramétrées (`server/utils/queries.ts`). Les `UPDATE` dynamiques n'interpolent que des noms de colonnes codés en dur.
- Validation serveur des entrées (`server/utils/validation.ts`) : types, longueurs, regex hex strict sur `color`. Les couleurs injectées en `:style` côté client sont donc sûres.
- Pas de `v-html`, `innerHTML` ou `eval` dans `app/`.
- Cookie de session chiffré (h3 `useSession`), `httpOnly` et `secure` par défaut. Secret vide = échec au démarrage, pas de fallback silencieux.
- Toutes les routes `/api/admin/*` mutatives appellent `requireAdminAuth` en première ligne.
- Mass assignment impossible : `updateCategory` / `updateTerm` ne lisent que les champs connus.
- `.env`, `.env.local`, `.vercel` ignorés par git. Aucun secret dans l'historique (les deux commits contenant `postgresql://` sont des placeholders de README et `.env.example`).
- CI avec `permissions: contents: read`.
- `pnpm audit --prod` : 1 vulnérabilité **low** (esbuild via `@nuxt/fonts`, dev server Windows uniquement).

### Constats

#### S1 — CSRF sur les endpoints admin (Majeur)

`server/utils/auth.ts:14-18` : `useSession` n'est appelé qu'avec `name`, `password`, `maxAge`. h3 1.15 (celui utilisé par Nitro 2.13) ne pose **pas** de `SameSite` par défaut (`DEFAULT_COOKIE = { path, secure, httpOnly }`). Firefox et Safari envoient alors le cookie sur les requêtes cross-site. Chrome applique Lax par défaut mais avec l'exception « Lax+POST » de 2 minutes après pose du cookie.

`readBody` parse `application/x-www-form-urlencoded`. Un formulaire HTML sur un site tiers `<form method="POST" action="https://.../api/admin/categories">` avec les champs `name`, `color`, `description` passe la validation (tous des strings) et **crée une catégorie** au nom de l'admin connecté. `POST /api/admin/terms` échoue par chance (`category_id` arrive en string, la validation exige un number). `PUT`/`DELETE` ne sont pas envoyables par un formulaire HTML.

Impact réel limité (création de catégories parasites) mais c'est un défaut structurel qui deviendra exploitable à la prochaine route ajoutée.

Correction :

```ts
// server/utils/auth.ts — factoriser la config
const SESSION_CONFIG = {
  name: 'admin-session',
  maxAge: 60 * 60 * 24 * 7,
  cookie: { sameSite: 'strict' as const },
}
```

Et en ceinture-bretelles, un middleware Nitro `server/middleware/origin.ts` qui rejette toute requête non-GET vers `/api/admin/` dont l'en-tête `Origin` (ou `Sec-Fetch-Site`) ne correspond pas à l'hôte.

#### S2 — Aucune protection contre le brute force sur `/api/admin/auth/login` (Majeur)

`server/api/admin/auth/login.post.ts` : pas de rate limiting, pas de délai, pas de verrouillage. Le nom d'utilisateur par défaut est `admin` (`nuxt.config.ts:25`). Un attaquant peut tester des mots de passe à la vitesse du réseau. Vercel n'ajoute rien par défaut.

Correction : rate limiter en mémoire par IP (5 tentatives / 15 min) suffit pour un admin unique. Sur Fluid Compute les instances sont réutilisées, donc un `Map` module-level tient dans la majorité des cas ; pour du durable, utiliser le Vercel Firewall (règle rate-limit sur le path) sans code.

#### S3 — Comparaison de mot de passe non constante en temps (Mineur)

`server/utils/auth.ts:10` : `password === config.adminPassword`. Timing attack théorique sur un secret. Remplacer par `crypto.timingSafeEqual` sur des buffers de même longueur (hasher les deux côtés avec SHA-256 avant comparaison pour égaliser les longueurs). Mieux : stocker un hash argon2/bcrypt dans `ADMIN_PASSWORD_HASH` plutôt que le mot de passe en clair dans l'env.

#### S4 — Aucun en-tête de sécurité HTTP (Majeur)

Ni `nuxt.config.ts` ni Vercel ne posent `Content-Security-Policy`, `X-Frame-Options`, `Strict-Transport-Security`, `Referrer-Policy`, `Permissions-Policy`, `X-Content-Type-Options`. La page admin est donc encadrable (clickjacking) et sans CSP en cas de XSS future.

Correction la plus simple : `routeRules` dans `nuxt.config.ts` :

```ts
routeRules: {
  '/**': {
    headers: {
      'X-Frame-Options': 'DENY',
      'X-Content-Type-Options': 'nosniff',
      'Referrer-Policy': 'strict-origin-when-cross-origin',
      'Permissions-Policy': 'camera=(), microphone=(), geolocation=()',
      'Strict-Transport-Security': 'max-age=31536000; includeSubDomains',
    },
  },
},
```

Une CSP demande un peu plus de travail (nonces pour les scripts inline Nuxt, whitelist `va.vercel-scripts.com` pour Analytics et Speed Insights). Le module `nuxt-security` gère tout ça en une config.

#### S5 — Sessions non révocables (Mineur)

`server/utils/auth.ts` : la session ne contient que `{ authenticated, username }`. Changer `ADMIN_PASSWORD` n'invalide pas les sessions existantes pendant 7 jours. Changer `SESSION_SECRET` les invalide toutes. Documenter ce comportement dans `SECURITY.md`, ou stocker dans la session un hash court du mot de passe et le comparer dans `getAdminSession`.

#### S6 — `parseInt` permissif sur les IDs de route (Mineur)

`[id].put.ts`, `[id].delete.ts`, `terms/[id].get.ts` : `Number.parseInt('12abc')` vaut 12. Pas exploitable (requête paramétrée) mais incohérent. Utiliser `Number()` + `Number.isInteger()`, ou la regex `/^\d+$/`.

#### S7 — Suppression de catégorie : erreur 500 pour une contrainte métier (Mineur)

`categories/[id].delete.ts:20-23` : la violation FK `ON DELETE RESTRICT` remonte en 500 avec un message qui devine la cause. Attraper le code Postgres `23503` et renvoyer un 409 explicite. Bonus : le 500 générique masque aujourd'hui les vraies erreurs.

#### S8 — Hygiène des dépendances (Mineur)

- `eslint`, `@nuxt/eslint`, `dotenv` sont dans `dependencies` au lieu de `devDependencies` (`package.json`). Ils partent dans le bundle serveur Vercel.
- Pas de `.github/dependabot.yml` ni Renovate. `SECURITY.md` promet des dépendances « régulièrement auditées ».
- Actions GitHub non épinglées par SHA (`actions/checkout@v4`). Risque supply chain faible mais réel.
- Pas de limite de taille de body sur `readBody`. Vercel plafonne à 4,5 Mo, acceptable.

#### S9 — Middleware client `admin.ts` : `useFetch` dans un middleware de route (Info)

`app/middleware/admin.ts:3` : fonctionne, mais `useFetch` est prévu pour les composants. En navigation client, il peut servir une réponse mise en cache par clé et ne pas re-vérifier la session après un logout dans un autre onglet. La sécurité réelle est côté serveur, donc c'est un problème UX. Utiliser `$fetch` avec try/catch.

### Priorités sécurité

1. S1 `sameSite: 'strict'` sur le cookie (une ligne) + vérification `Origin` sur `/api/admin/*`.
2. S4 en-têtes de sécurité via `routeRules`.
3. S2 rate limiting sur le login (Vercel Firewall ou middleware Nitro).
4. S3 comparaison constante + hash du mot de passe.
5. S8 déplacer les deps dev, ajouter Dependabot.

## Partie 2 — Accessibilité (WCAG 2.2 AA)

Rapport produit par l'agent accessibilité, spot-checké sur les points structurants. Constat transversal : `grep -rn "aria-|role=|tabindex|focus-visible|sr-only|\.focus()|reduced-motion" app/` retourne **zéro** résultat. L'app repose entièrement sur la sémantique native, bonne sur les formulaires admin, absente sur les composants interactifs sur mesure. Ratios de contraste calculés (formule WCAG), pas estimés.

### Critique

#### C1 — Aucun `lang` sur le document (3.1.1)

`nuxt.config.ts` sans `app.head.htmlAttrs`, aucun `useHead`. Les lecteurs d'écran lisent le français avec une voix anglaise.

```ts
app: { head: { htmlAttrs: { lang: 'fr' } } },
```

#### C2 — FlashCard inaccessible au clavier et révèle la réponse aux lecteurs d'écran (2.1.1, 4.1.2, 1.3.1)

`app/components/FlashCard.vue:2-6` : `<div @click="flip">` sans `tabindex`, `role`, ni gestionnaire clavier. Les deux faces sont dans le DOM, la face arrière masquée uniquement par `backfaceVisibility: hidden` (visuel). Un lecteur d'écran lit radical puis signification d'un coup : l'exercice n'existe pas pour cet utilisateur.

Correction : conteneur en `<button type="button" :aria-pressed="isFlipped">`, `:aria-hidden` sur la face cachée, `h2`/`h3` remplacés par `<p>` (un radical n'est pas un titre), « Cliquez pour révéler » remplacé par « Appuyez pour révéler ».

#### C3 — Raccourcis clavier globaux cassants et fuite du listener (2.1.1, 2.1.4)

`app/pages/flashcards.vue:218-233` : `preventDefault()` sur Espace dans un listener `window` non filtré. Focus sur « Suivant » + Espace retourne la carte au lieu d'activer le bouton. Dans le `<select>` mobile, les flèches changent la catégorie **et** la carte.

Second problème, vérifié : `onUnmounted` est enregistré **après un `await`** dans `onMounted`. Vue perd l'instance courante après l'await, le hook ne s'enregistre pas, le listener survit à la navigation. Après une visite de `/flashcards`, Espace est intercepté sur toutes les pages jusqu'au rechargement.

```ts
function handleKeyPress(e: KeyboardEvent) {
  const t = e.target as HTMLElement
  if (['INPUT', 'SELECT', 'TEXTAREA', 'BUTTON', 'A'].includes(t.tagName)) return
  if (e.key === 'ArrowRight') nextCard()
  else if (e.key === 'ArrowLeft') previousCard()
}
onMounted(() => window.addEventListener('keydown', handleKeyPress))
onUnmounted(() => window.removeEventListener('keydown', handleKeyPress))
```

Avec C2 corrigé, le raccourci Espace global devient inutile.

#### C4 — Feedback du quiz jamais annoncé (4.1.3)

`app/components/QuizQuestion.vue:92-107` : le bloc feedback apparaît via `v-if` sans `aria-live`. Les boutons de réponse passent en `disabled`, ce qui éjecte le focus vers `<body>`. Ajouter `role="status" aria-live="polite"` sur le feedback et déplacer le focus vers le bouton « Question suivante » dans `nextTick`. Idem pour le score (ligne 9).

#### C5 — Modales admin sans rôle, sans piège de focus, sans gestion du focus (2.4.3, 4.1.2)

`admin/categories.vue:115-192`, `admin/terms.vue:203-276` : quatre `<div class="fixed inset-0">` sans `role="dialog"`, `aria-modal`, `aria-labelledby`. Le focus reste sur le bouton déclencheur derrière l'overlay. Échap ne ferme rien. Le focus n'est pas restitué à la fermeture.

Correction recommandée : `<dialog>` natif avec `showModal()` (piège de focus, Échap et `aria-modal` gratuits). `role="alertdialog"` pour les confirmations de suppression.

#### C6 — Boutons et liens icône seuls sans nom accessible (4.1.2, 2.4.4, 1.1.1)

- `admin/categories.vue:67-94`, `admin/terms.vue:127-154` : boutons modifier/supprimer = `<button><svg/></button>`, annoncés « bouton » sans nom. Impossible de savoir quel terme on supprime.
- Liens retour `<NuxtLink><svg/></NuxtLink>` dans `flashcards.vue:16`, `quiz.vue:16`, `admin/categories.vue:16`, `admin/terms.vue:16`.

```vue
<button type="button" :aria-label="`Supprimer la catégorie ${category.name}`">
  <svg aria-hidden="true" focusable="false" …>
```

Tous les autres SVG décoratifs à côté d'un texte : `aria-hidden="true" focusable="false"`.

#### C7 — Contraste de texte insuffisant, palette systémique (1.4.3)

Seuils : 4,5:1 texte normal, 3:1 texte large.

| Combinaison                           | Ratio       | Usage                                                                                | Verdict                              |
| ------------------------------------- | ----------- | ------------------------------------------------------------------------------------ | ------------------------------------ |
| `text-deep-teal/60` sur crème         | 2,77        | ~25 occurrences en `text-sm` (compteurs, sous-titres, labels)                        | Échec                                |
| `text-deep-teal/70` sur crème         | 3,43        | `index.vue:101`, `error.vue:18`, `admin/terms.vue:114`                               | Échec                                |
| Terracotta `#C1666B` sur blanc        | 3,90        | Messages d'erreur en 14px (`login.vue:61`, `quiz.vue:144`, `categories.vue:167,188`) | Échec                                |
| Blanc sur `bg-terracotta`             | 3,90        | Boutons « Voir les résultats », « Supprimer »                                        | Échec                                |
| `text-yellow-600` sur `bg-yellow-100` | 2,74        | Score résultats `quiz.vue:189-197`                                                   | Échec même en large                  |
| Blanc sur couleurs de catégorie (DB)  | 2,15 à 4,83 | FlashCard, cartes index, badges admin                                                | 6/11 couleurs échouent même en large |

Corrections :

- Token `--color-deep-teal-muted: #4a7674` (≈ 4,6:1 sur crème) et remplacer `/60` et `/70` par `sed`.
- Erreurs en `text-red-700` (6,5:1 sur blanc). Terracotta réservé aux titres ≥ 24px ou assombri à `#A84E53`.
- Couleurs de catégorie saisies librement par l'admin : la correction doit être **algorithmique**. Ajouter `app/utils/color.ts` avec une fonction `readableTextOn(hex)` qui retourne blanc ou `#111827` selon la luminance, et l'appliquer sur FlashCard, `index.vue`, `admin/terms.vue`. Supprimer les `text-white/70` et `/80`. Alternative plus robuste sur les flashcards : fond blanc avec la couleur de catégorie en bordure épaisse. Ajouter un avertissement en temps réel dans `CategoryForm.vue` si le ratio < 4,5.
- Résultats : `-800` sur `-100` (yellow-800/yellow-100 ≈ 6,4:1).

### Majeur

#### M1 — Labels de formulaire non associés (1.3.1, 4.1.2, 3.3.2)

- `quiz.vue:44` : label « Catégorie » sans `for`, select sans `id`.
- `quiz.vue:58` : label « Type de questions » devant un groupe de boutons. Utiliser `<fieldset><legend>`.
- `quiz.vue:111-122` : range « Nombre de questions » sans `id`. La valeur affichée devrait être un `<output>`.
- `admin/terms.vue:48-69` : « Rechercher » et « Filtrer par catégorie » sans `for`/`id`.
- `CategoryFilter.vue:7-16` : select mobile sans label (le titre est `hidden` sous `lg`). Ajouter `aria-label`.
- `CategoryForm.vue:18-26` : `<input type="color" id="color-picker">` sans label.

#### M2 — Erreurs de formulaire silencieuses ou non annoncées (3.3.1, 4.1.3)

- `login.vue:61`, `CategoryForm.vue:71`, `TermForm.vue:66` : `<p v-if="error">` sans `role="alert"` ni `aria-describedby`.
- Bug fonctionnel : `CategoryForm.vue:98-113` et `TermForm.vue:94-109` entourent un `emit()` synchrone d'un `try/catch` qui ne peut jamais capturer l'échec réseau. Les parents (`categories.vue:252`, `terms.vue:399,426`) avalent l'erreur avec un `// TODO`. Un échec de création/modification/suppression est invisible pour **tous** les utilisateurs, la modale reste ouverte sans explication.

#### M3 — Groupes de boutons « sélection » sans état exposé (4.1.2, 1.4.1)

`quiz.vue:62-105` (QCM / Vrai-Faux / Mixte) et `CategoryFilter.vue:21-53` : la sélection n'est signalée que par la couleur. Aucun `aria-pressed`. Solution la plus juste : `<fieldset>` + `<input type="radio">` stylés via `peer-checked:`.

#### M4 — Perte de focus après chaque action (2.4.3)

`quiz.vue:164-181` : « Question suivante » devient `disabled` → focus éjecté vers body à chaque question. `finishQuiz()` et `startQuiz()` : nouveau contenu monté, focus perdu, rien annoncé. `flashcards.vue:155-172` : idem sur la dernière carte. Déplacer le focus vers le titre de la question (`tabindex="-1"`) dans `nextTick`.

#### M5 — Contraste des composants d'interface (1.4.11, 2.4.7)

- Bordures de champs `border-deep-teal/20` = 1,36:1 et `border-gray-300` = 1,47:1 (seuil 3:1). Les options de réponse du quiz (`QuizQuestion.vue:148`) n'ont que cette bordure comme délimitation. Passer à `border-gray-500` ou `border-deep-teal/50`.
- `quiz.vue:421-430` : `.slider { outline: none }` sans remplacement `:focus-visible`. **Aucun indicateur de focus** sur le curseur.
- `admin/terms.vue:143` : icône supprimer `text-terracotta/60` = 2,15:1 (`categories.vue:83` utilise `text-red-700`, aligner).
- Pastilles de couleur de catégorie sur blanc : 7/11 couleurs < 3:1. Ajouter `border border-gray-400`.

#### M6 — Champ identifiant sans `autocomplete="username"` (1.3.5)

`login.vue:28-35`.

#### M7 — Landmark `<main>` absent sur 6 pages sur 7 (1.3.1, 2.4.1)

Seule `flashcards.vue:63` a un `<main>`. Navigation par région impossible ailleurs.

### Mineur

- **m1** Hiérarchie de titres avec sauts (h1 → h3) sur `flashcards`, `quiz`, `admin/index`, `admin/categories`, `error.vue`. Sur `index.vue`, le `h1` est le nom de marque dans la nav, le vrai titre est en h2.
- **m2** Barres de progression (`QuizQuestion.vue:13-18`, `flashcards.vue:120-127`) sans `role="progressbar"`.
- **m3** Aucune prise en charge de `prefers-reduced-motion` : flip 3D 0,6s, fadeInUp, canvas-confetti jusqu'à 200 particules sans garde. Critère AAA mais correction triviale (media query globale dans `main.css` + `matchMedia` avant `triggerConfetti`). Note : `duration-600` Tailwind et le `transition` du `<style scoped>` de FlashCard font doublon.
- **m4** États de chargement sans `role="status"` (`flashcards.vue:65`, `categories.vue:45`, `terms.vue:80`).
- **m5** Tableau admin (`terms.vue:92-159`) sans `<caption>`, sans `scope="col"`, sans ligne « aucun résultat », pagination hors `<nav>` et sans `aria-current="page"`.
- **m6** `✓` / `✗` lus littéralement (`QuizQuestion.vue:98`). Entourer d'un `<span aria-hidden="true">`.
- **m7** Chiffre 404 `text-deep-teal/20` = 1,35:1 (`error.vue:12`). Soit `aria-hidden`, soit `/40`.
- **m8** Lien « Administration » `hidden sm:inline` (`index.vue:12`) et aide clavier `hidden md:flex` (`flashcards.vue:110`) disparaissent à 200 % de zoom (1.4.10 à la limite).
- **m9** Cibles tactiles (2.5.8) : **conforme**. Liens retour à 24px exactement, `p-1` recommandé pour le confort.

### Points vérifiés conformes

- Pas de timer dans `useQuiz.ts` (2.2.1 non applicable).
- Feedback quiz : couleur et texte (1.4.1 respecté), ratios `green-700/green-50` 4,79 et `red-700/red-50` 5,91.
- Formulaires admin : labels associés par `for`/`id`, `required` natif, `pattern` hex.
- Tailwind v4 ne supprime pas `outline`. Les inputs avec `focus:outline-none` ont un remplacement visible, sauf le slider (M5).
- Ordre DOM = ordre visuel. Aucun `tabindex` positif.
- Confirmation explicite avant suppression (3.3.4).

17 critères WCAG 2.2 AA distincts en échec. Les échecs de niveau A (2.1.1, 4.1.2, 1.1.1, 3.1.1, 2.4.3, 3.3.1) bloquent l'usage clavier et lecteur d'écran des deux fonctionnalités cœur (flashcards, quiz) et de l'admin.

### Priorités accessibilité

1. **C1** `lang="fr"` dans `nuxt.config.ts`. Une ligne.
2. **C2 + C3** FlashCard en `<button aria-pressed>` avec `aria-hidden` sur la face cachée, suppression du raccourci Espace global, `onUnmounted` enregistré de façon synchrone. Corrige aussi un bug fonctionnel réel (listener qui fuit).
3. **C4 + M4** `role="status"` sur le feedback quiz et déplacement de focus à chaque transition.
4. **C7** Token `deep-teal-muted`, erreurs en `red-700`, couleur de texte calculée selon la luminance de la catégorie. Chantier le plus étendu (~30 occurrences) mais mécanique.
5. **C5 + C6 + M1 + M2** Modales en `<dialog>` natif, `aria-label` sur les 12 boutons/liens icône, `for`/`id` sur les 6 champs orphelins, remontée des erreurs réseau dans les formulaires admin.
